# 运行与排障

## 日常操作

从资源管理器双击 `start.bat`，或在自己长期使用的终端运行 `python tools/stack.py start`。先启动外部 QQ/SnowLuma，再启动监控与可选 MaiBot。`status` 会实际连接端口核对；`stop` 只处理本发布目录记录且身份匹配的服务，不管理 QQ/SnowLuma。

安装新版本前，停止本实例并备份实际生效的 config、data 和插件持久数据。解压新源码后保留自己的配置；不要用作者生产目录覆盖新实例。若修改了 PowerShell 脚本，保存 UTF-8 BOM，供 Windows PowerShell 5.1 正确识别中文。

## 分层检查

1. QQ/SnowLuma：机器人号是否登录并成功桥接，3000/3001 是否可连接，token 是否一致。WS 地址用普通 HTTP 请求可能返回 426，这是服务在要求升级协议，不代表请求失败。
2. 监控：8080 面板可访问、OneBot 状态已连接、已填群列表。在自己的测试群发一条普通消息并确认可检索。
3. MaiBot：查看自己的 MaiBot 日志，确认插件已加载、WS 已连接、模型调用成功，再确认实际 QQ 收到回复。
4. 可选能力：审核/记忆/识图/搜索分别检查，不能仅凭一个聊天回复判断整栈全部正常。

## 常见原因

| 现象 | 优先检查 |
|---|---|
| 面板能开但没有消息 | 监控群列表、OneBot token、QQ 登录与桥接状态。 |
| QQ 重启后停止响应 | SnowLuma 是否仍连接到正确的机器人账号。 |
| 本机 curl 正常但 Python 报连接错误 | 代理环境变量，确保回环地址加入 NO_PROXY。 |
| 模型 401/402 | 凭据、账户余额或权限，按服务商返回处理。 |
| 模型 429/超时 | 配额、并发、服务商限流与网络。 |
| 记忆一直为空 | embedding 请求与存储状态，不能只测回复模型。 |
| 8080/8090 被占用 | 先看 status 与已有实例，不要盲目杀进程。 |

发布验证只检查源码、模板、启动器及隔离的本地运行。你自己的 QQ 登录、外部桥接、模型额度和真实群消息投递需在自己的环境验证。
